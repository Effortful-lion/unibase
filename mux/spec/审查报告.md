## 二、P0 — 已修复

### P0-1: `GetNodes` 未排除自身节点 ✅

**位置**：`internal/cluster/manager.go:77-90`（`GetNodes`）

**修复**：在 `GetNodes` 中增加 `node.Tag != cm.self.Tag` 判断，确保无论节点来源如何，自身节点始终被排除。

```go
func (cm *ClusterManager) GetNodes(group string, role Role) []ClusterNode {
    cm.nodesMu.RLock()
    defer cm.nodesMu.RUnlock()

    nodes := make([]ClusterNode, 0)
    cm.nodes.Range(func(_, v any) bool {
        node := v.(ClusterNode)
        if node.Tag == cm.self.Tag {
            return true
        }
        if node.Group == group && node.Role == role && node.IsAlive(cm.nodeTTL) {
            nodes = append(nodes, node)
        }
        return true
    })
    return nodes
}
```

### P1-2: Pipeline 中间件链职责澄清 ✅

**结论**：不修改代码，明确设计意图。

REST 路由通过 `engine.httpEngine.GET(path, handler)` 直接注册到 gin，受 `engine.Use()` 注册的 gin 中间件影响。`pipeline.Use()` 注册的中间件仅作用于 Cmd 路由。这是有意设计：REST 路由使用 gin 原生中间件生态，Cmd 路由使用 mux 统一的中间件链。

## 四、P2 — 部分修复

### P2-1: `Conn.Write` 竞态窗口 ✅

**位置**：`internal/websocketx/conn.go:97-116`

**修复**：将三次 `select` 合并为带循环的单逻辑块，消除 `doneCh` 在两次 select 之间关闭的竞态窗口。

```go
for {
    select {
    case c.sendCh <- data:
        return nil
    case <-c.doneCh:
        return fmt.Errorf("websocketx: write on closed connection")
    default:
        // 队列满：丢弃最旧消息，doneCh 关闭时立即返回
        select {
        case old := <-c.sendCh:
            _ = old
        case <-c.doneCh:
            return fmt.Errorf("websocketx: write on closed connection")
        }
    }
}
```

### P2-2: `runSession` 断开原因区分 ✅

**位置**：`internal/websocketx/hub.go:106-120`

**修复**：使用 `websocket.IsCloseError` 区分正常关闭（`CloseNormalClosure`/`CloseGoingAway`）和异常断开。正常关闭静默退出，异常断开发送错误响应后断开。

```go
msg, err := session.conn.Read(ctx)
if err != nil {
    if websocket.IsCloseError(err, websocket.CloseNormalClosure, websocket.CloseGoingAway) {
        break // 正常关闭，静默退出
    }
    // 异常断开：向客户端发送错误响应后断开
    _ = session.Conn().Write(ctx, &CmdMessage{
        Cmd:  "unknown",
        Meta: map[string]interface{}{"code": "10500", "message": err.Error()},
    })
    break
}
```

### P2-3: `discoveryLoop` 增量更新 ✅

**位置**：`internal/cluster/manager.go:118-160`

**修复**：替换全量清空再重建为增量更新策略。构建新节点集合后，只删除不存在于新集合中的旧节点，只添加新集合中新增的节点。

```go
// 构建新节点集合（排除自身）
newNodes := make(map[string]ClusterNode, len(nodes))
for _, node := range nodes {
    if node.Tag != cm.self.Tag {
        newNodes[node.Tag] = node
    }
}

// 增量更新
cm.nodesMu.Lock()
var toDelete []string
cm.nodes.Range(func(key, _ any) bool {
    tag := key.(string)
    if _, ok := newNodes[tag]; !ok {
        toDelete = append(toDelete, tag)
    }
    return true
})
for _, tag := range toDelete {
    cm.nodes.Delete(tag)
}
for tag, node := range newNodes {
    cm.nodes.Store(tag, node)
}
cm.nodesMu.Unlock()
```
